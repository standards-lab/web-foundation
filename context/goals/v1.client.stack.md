## Task brief · template

**Problem**

The `template` branch has the CLI and its standalone kind, but its written project sits on
web-foundation v0.3.0 and web-components v0.1.0, uses the theme menu v0.4.0 removes, and lays out
its own page. This task moves it onto the layers' application page, icons, and Settings and Help,
adopts marathon 0.23.0, holds comments to the five kinds, fixes the review findings, and releases
v0.1.0. The embedded kinds wait for `embedded`.

**Behaviors**

1. `webappgen new standalone <dir>` writes the shared starter, then the kind's files, filling
   --name (default: dir's name), --title (default: name), --base (default "/"), and --api-base
   (default "/api/"). It never prompts. A non-empty dir, a missing dir, an unknown flag, or a
   --base not beginning with "/", unclean, or with a query or fragment is a usage error naming
   the fix, and nothing is written. On success it prints the next steps (mise install, mise run
   install, mise run check) and exits 0.
2. --install then runs mise install and mise run install there; a missing mise or failing step
   exits nonzero naming the step, and the files stay.
3. `webappgen version` prints the release built from, or (devel). Help covers every command, `new`
   lists its kinds, and exit codes are go-core's.
4. The written project is private and takes web-foundation v0.4.0, web-icons v0.1.0,
   web-components v0.2.0, web-app-sdk v0.1.0, and web-tooling v0.1.0 by exact github: release
   tag, with a committed lockfile. Its tools pin chrome-headless-shell for linux-x64, linux-arm64,
   mac-x64, and mac-arm64. Its mise config has one comment naming the webappgen version that wrote
   it, and no webappgen pin. A short README covers its tasks (install, check, dev, preview, build,
   currency), config.json, and deploying.
5. The written page:
   - --base is written as <base href>, and Vite's base agrees. A render-blocking module applies
     the stored theme (web-foundation.* keys) before first paint. It takes the full entry, with
     every built-in profile.
   - It is the foundation's application page type, laid out by the layout sheet alone. The header
     holds the title and, at its inline end, glyph buttons Help (?) and Settings (S).
   - Help is a fit-width dialog holding sl-shortcuts, listing S and ?. Settings is a wide dialog
     holding sl-settings: color zen, github, catppuccin, everforest; space regular, compact; type
     mono, sans; a change applies and is stored at once.
   - Each dialog's header has Close with its Esc hint; Close and Escape close it with no script,
     and focus returns to the opener.
   - web-icons' marker fill draws question-16, gear-16, and x-16, in dev and the build.
   - web-app-sdk's router serves a home view (plain content, no component) and a not-found view
     under the base; a deep link or a reload on a fallback host reaches the right view.
   - Dev and preview tasks; no fonts pin.
6. The config reader takes #app-config when present, else fetches config.json relative to the
   base; a missing, non-JSON, or wrong-shaped config fails naming the element or file. The public
   directory's config.json holds --api-base, carried by dev, preview, and build.
7. The written project's check passes: lint, types, unit, build, size (raw, gzip, brotli totals by
   node:zlib, no budget), and a Chromium browser tier on web-tooling v0.1.0 against the built site
   covering home, not-found, a deep-link reload, the stored theme before first paint, S and ?
   opening their dialogs, Escape closing each with focus returning, a setting applying at once and
   surviving a reload, and every glyph filled with no marker left.
8. currency exits 0 for the CLI and a written project, except the holds: typescript 6.0.3
   (typescript-eslint's range) and rolldown at the newest in vite 8.3.8's range.
9. The embedded trees hold only tracked files. The starter's tool pins equal the CLI's root pins.
10. A vX.Y.Z tag on main's merge commit releases the CLI: it refuses a tag off main, runs the
    check, builds linux and darwin on amd64 and arm64 with cgo off, refuses a binary whose
    `version` isn't the tag, and attaches webappgen-vX.Y.Z-<os>-<arch>.tar.gz (binary, LICENSE)
    and SHA256SUMS to a draft from the tag's CHANGELOG section, publishing once all are attached.
11. Docs and review findings:
    - README: installing (mise use github:standards-lab/webappgen, go install ...@latest), WSL,
      `new standalone` with its flags and --install, Settings and Help, deploying, and the
      capability map.
    - STANDARDS: the spike's applicable judgement calls with pointers; the graph rule points to
      Go Elemental's CLI applications page; the key-binding and TypeScript-tests rules lose their
      unsupported pointers.
    - The agent instructions and context cite standards-lab/roadmap/index.toml.
    - Every file copied from spike-html-apps (2883d78) carries provenance, starter files included;
      the Settings and Help markup names web-components (6052866); JSON provenance lives in the
      context.
    - CHANGELOG 0.1.0 is dated the release day and names behavior 4's tags, Settings and Help,
      and its sources.
12. Marathon: mise pins its tools at 0.23.0; the check runs lint-context and lint-references and
    fails if either fails or is missing; capability-map entries are marked built or planned (the
    embedded kinds planned, v0.2.0); the CI wait moves to `[remote] checks`, out of merge.
13. Comments: every comment, starter and kind files included, is one of comments.md's five kinds;
    reasoning moves to the written README, webappgen's README, or names. A written project's lint
    requires descriptions on ESLint directives (eslint-plugin-eslint-comments 4.8.1) and allows
    a TypeScript directive only with one (ban-ts-comment, allow-with-description). The CLI's lint
    still requires a reason on each suppression.

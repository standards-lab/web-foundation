## Task brief · v1.client.stack · newclient

```
Problem       The template serves an app's embedded Vite build through
              go-web-sdk, but go-web-sdk has no handler for it. The
              spike's handler is proven, but it sits in a staging package
              with its spike name, takes required fields in its options,
              and sends no validators, so every revalidation re-sends the
              whole body.
Behaviors     1. web.NewClient(dist, entry, ClientOptions{Base, Title,
                 RenderBlocking, Config}) returns the handler. It reads
                 Vite's manifest from dist once, at construction, and
                 fails with an error naming the problem when the
                 manifest is missing or corrupt, when the entry or a
                 RenderBlocking key is missing, or when the config can't
                 be encoded. An empty Base is "/". A Base that doesn't
                 begin with "/", isn't clean, or carries a query or
                 fragment panics naming the fix, as a malformed prefix
                 does.
              2. The shell writes <base href> (Base with one trailing
                 slash), the title escaped as text, and the config as
                 JSON in <script type="application/json" id=
                 "app-config">. No config value can close that element,
                 and its content decodes back to the value; a nil
                 config writes null. The shell names the CSS of every
                 module it loads and of their static imports, a
                 modulepreload for each statically imported chunk that
                 no script loads, then each RenderBlocking module with
                 blocking="render" in the order given, then the entry.
                 Nothing from a dynamic import appears, and each file is
                 named once.
              3. Every path that isn't an asset or a missing asset is a
                 client route and answers the shell as text/html with
                 no-cache. That includes deep links, trailing slashes,
                 and ".." paths, which are cleaned inside the build.
              4. A build file answers its bytes, typed by its extension.
                 Under the manifest's directories it is cached as
                 public, max-age=31536000, immutable; any other is
                 no-cache. The shell and every no-cache file carry a
                 strong ETag, a hash of their content taken once at
                 construction. A matching If-None-Match answers 304
                 with no body.
              5. A missing asset (a path under the manifest's
                 directories, a dotfile or dot-directory path, or a last
                 segment with an extension, with no file behind it)
                 answers a 404 problem, never the shell. The manifest
                 and every other dotfile are never served. The
                 problem's instance is the path the browser asked for,
                 Base included.
              6. Only GET and HEAD are answered. Any other method gets a
                 405 problem with Allow: GET, HEAD. HEAD answers GET's
                 status, Content-Type, Content-Length, Cache-Control and
                 ETag with no body.
              7. Set as the Router's not-found handler at "/", it
                 answers only what no module and no native route claims,
                 and the probes and modules answer as before. Mounted
                 with NewHandlerModule under a prefix, the bare prefix
                 redirects (301) to prefix/ with its query kept, and
                 every path beneath it answers as above.
              8. The web package's doc comment, README, and capability
                 map name NewClient, ClientOptions, ManifestPath and
                 ConfigElementID. The middleware-sourcing note names an
                 embedded client's JS and CSS as a candidate trigger
                 for the compression middleware. Outside the CHANGELOG
                 and context provenance, no spike name appears.
              9. currency exits 0.
              10. CHANGELOG has a v0.18.0 section that names NewClient
                  as Added and spike-html-apps (2883d78) as its source.
                  go.mod's requirements are unchanged.
Test seams    The handler NewClient returns, driven with httptest over
              fstest.MapFS builds (the spike's manifest fixture carried
              forward), on its own and mounted through web.Router, both
              as the not-found handler and as a NewHandlerModule.
Slices        1. Upgrade slice: jdx/mise-action v5.2.7 -> v5.2.10.
                 Demo: the check, and currency exiting 0.
              2. Construction and the shell: the constructor, its errors
                 and panics, the shell's contents and order, and every
                 path answering the shell (behaviors 1-3).
                 Demo: the check and the shell tests.
              3. Serving: assets and cache policy, ETag and 304, missing
                 assets, dotfiles, methods and HEAD, the root and prefix
                 mounts (behaviors 4-7).
                 Demo: the check and the router tests at each mount.
              4. v0.18.0 prepared: the package doc's section, README,
                 capability map, middleware-sourcing note, CHANGELOG
                 with provenance (behaviors 8, 10).
                 Demo: the check and go doc web.NewClient.
Out of scope  Compression (go-web-sdk's backlog gzhttp middleware);
              CORS and ValidateOrigin (v1.middleware); a mount helper; a
              shell lang option or other i18n; serving an external
              build; a test against a real Vite build (the template's);
              moving go-web-service or go-web-sdk-template onto v0.18.0;
              a release of middleware/rate-limit.
Door          one-way for the v0.18.0 tag, which the module proxy and
              checksum database pin; two-way otherwise.
Release       v0.18.0
```

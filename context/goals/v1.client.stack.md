## Decisions

- plan: each repository starts fresh at v0.1.0, seeded by copy from its archived spike with a
  provenance line on every copied file; never a repository transfer, and the spike is never a
  dependency.
- plan: root is web-foundation, the layer every other builds on and the repository of two tasks;
  rejected web-tooling (first task only) and web-app-sdk-template (last task only).
- plan: `order` places the five as their own chain, web-tooling → web-foundation →
  [web-components, web-app-sdk] → web-app-sdk-template, between the templates' layer and
  go-web-service; rejected spreading them into the Go layers. They stay outside `exclusive`.
- plan: per-task locks: `newclient` adds go-web-sdk (and so the exclusive group) to the goal's
  repos for that task only, dropping it at its SHIP; `standard` adds architecture for that task
  only.
- plan: the catalog declares no `standard = "web-elemental"` until `standard` founds it; until
  then each entry cites the preliminary standard, web-client.md "Toward Web Elemental".
- plan: web-tooling v0.1.0 includes the pinned DejaVu font-set helper from spike-html-go-wasm;
  web-foundation doesn't adopt it.
- plan: Firefox's missing `blocking="render"` is accepted (a one-frame theme flash for readers
  with a non-default stored theme); no inline head script. Revisit when Firefox ships it.
- plan: Safari's missing CSS module scripts mean a page using the components or the theme menu
  requires a Vite build; the packages keep the standard syntax, no pack-time rewrite. Revisit
  when Safari ships it.
- plan: `palettes` refines the color profiles from https://terminalcolors.com/; the site states
  no license, so each palette's upstream license is checked before use.
- plan: tooling → foundation stay lean: sites.status-reports and sites.training.foundation are
  staged by a `plan` once web-foundation v0.1.0 is tagged.
- plan: init commits carry only the marathon setup; each repository's first task seeds its code,
  toolchain, CI, and release workflow.
- tooling: `release.yml` runs on the hand-pushed annotated `vX.Y.Z` tag instead of cutting the tag
  on a push to main, as the spike did. It verifies the tag (one parent, a merge commit on main,
  whose `package.json` version the tag names), runs the check, diffs the pack against the tag's
  tree, and publishes.
- tooling: the DejaVu font directory comes from `DEJAVU_FONTS`, as `BROWSER_EXECUTABLE` names the
  browser; the package ships no fonts.
- tooling: currency reads DejaVu's latest from its release asset names sorted by version, since
  mise's http backend lists them unsorted.
- tooling: the screenshots tests' stub PATH holds only the stub directory and a node symlink, so a
  node in /usr/bin can't let the real kitty or xdg-open bypass the stubs.
- tooling: held typescript at 6.0.3: 7.0.2 is outside typescript-eslint 8.73.0's range
  (`>=4.8.4 <6.1.0`); currency compares typescript against that range's newest.
- tooling: the JSON files' provenance (`package.json`, `.prettierrc.json`) lives in web-tooling's
  `context/README.md`, since JSON takes no comment.
- tooling: release.yml runs on `workflow_dispatch` with the tag, from main: a tag push reads workflows
  from the tagged tree, which holds only the pack, so the push trigger never fired (fixed forward in
  web-tooling #2); v0.1.0 kept its first cut, whose parent is main's merge commit, and released.

- foundation: released as v0.1.0 in this task (plan round 1).
- foundation: the spike's storage and Symbol.for keys, `spike-html-apps-foundation.*`, are renamed
  `web-foundation.*` before v0.1.0, so no reader's stored settings are lost by a later rename; the
  layers above use the same names (plan round 1).
- foundation: the unit test comparing the emitted `format.d.ts` with the spike's v0.1.0 fixture is
  dropped (spike history, and confusable with web-foundation's own v0.1.0; the types step already
  checks the suite against the built declarations); the half where tsc refuses runtime code in a
  declaration file stays.
- foundation: the pack holds only `dist/`, README, LICENSE, and `package.json`; CHANGELOG stays
  out, as in web-tooling, and the release workflow reads it from the tag's parent on main.
- foundation: the pack commit and tag are cut by hand with README's "Release" steps (`git
  commit-tree` on main's merge commit), as in web-tooling; there is no pack tooling.
- foundation: `package.json` carries no `repository` field (the spike's had none), matching
  web-tooling's manifest.
- foundation: the workflow files name web-tooling (1ff49e4) as their immediate source.
- foundation: the storage-key tests assert that the `web-foundation.*` key is the only one
  written, which proves the name without writing the spike's name into the tests.
- foundation: define, emit, and required gained browser tests against `dist/dom.js`; the spike had
  none.
